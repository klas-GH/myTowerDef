=== v 1.8.1 =====
- Removed a dead `const TOWER_COST = 50;` leftover from the pre-type era; placement now derives every cost from the authoritative TOWER_TYPES only.
- Sell is hardened against double refunds: selling a tower that is no longer placed (already sold or cleared by restart) is a safe no-op, so repeated calls never duplicate coins.
- Switching tower type is centralized in a single `selectTowerType()` helper that always clears any existing tower selection, so the upgrade panel can never show a stale tower after a type switch.
- Extended regression.js with deterministic maintenance checks: exact purchase deduction per type, insufficient-funds rejection at the boundary, full-refund sell across all types and upgrade levels, sell removes only the intended tower, no double refund, no actions after defeat, switch type clears tower selection, restart resets economy.

=== v 1.8.0 =====
- Introduced three distinct purchasable tower types (Archer, Cannon, Magic) with a centralized TOWER_TYPES definition used by placement, combat, rendering, the placement ghost, and the upgrade panel.
- Archer (50/20/85/0.65) is the baseline; Cannon (90/45/75/1.00) deals heavy damage slowly; Magic (80/28/110/0.85) has the longest range. Each has a real cost/damage/range/cooldown trade-off.
- Added a compact 3-button tower picker above the controls; selecting a type clears any tower selection and shows its cost.
- Placement uses the selected tower type and deducts its specific cost exactly once; failed placements never charge.
- Added a Sell button on the upgrade panel: selling a tower refunds its full purchase cost plus every upgrade cost already spent (no loss).
- Placement ghost now draws the selected tower type's color and range ring.
- Towers render with per-type color and a shape glyph so types are distinguishable without relying on color alone.
- Preserved existing direct placement, upgrades, combat, enemy archetypes, wave progression, victory, defeat, and restart.
- Extended regression.js with deterministic tower-type, selection, placement, sell, upgrade, and restart tests.

=== v 1.7.0 =====
- Streamlined tower placement: removed the separate Build button. Tapping a green spot now places a tower directly (validated: not wave-active, not game-over, not occupied, coins sufficient). Tapping an existing tower still selects it for upgrade.
- Only Start Wave and Restart remain as controls; the control panel is now a vertical two-button layout.
- Added a lightweight placement preview (ghost tower on the nearest valid spot; green = placeable, red = blocked) derived from the actual placement rules.
- Currency is deducted exactly once per successful placement; failed placements never charge.
- Extended regression.js with deterministic placement, rejection, and restart tests.

=== v 1.6.0 =====
- Introduced three distinct enemy archetypes (Standard, Runner, Armored) with a centralized ENEMY_TYPES definition used by spawning, combat, rendering, and the wave preview.
- Wave composition is now data-driven: WAVE_DEFS specify explicit, deterministic enemy type counts per wave (wave 1: 8 Standard; wave 2: 6 Standard + 4 Runner; wave 3: 4 Standard + 4 Armored + 4 Runner).
- Per-type rewards are awarded on defeat (Standard 10, Runner 14, Armored 18) instead of a flat 10.
- Enemies render with per-type color and a shape glyph so archetypes are distinguishable without relying on color alone.
- The next-wave preview now shows per-type counts derived from the same authoritative composition used by spawning.
- Preserved existing manual wave starts, preparation phase, tower placement, upgrades, combat, victory, defeat, and restart behavior.
- Extended regression.js with deterministic enemy-archetype, composition, spawn-queue, reward, and preview tests.
